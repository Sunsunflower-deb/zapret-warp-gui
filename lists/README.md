# Списки хостов и IP

Формат файлов — как у zapret: **по одному значению на строку, без комментариев**.
Строки с `#` в файле не документированы апстримом, поэтому их лучше не использовать:
для пояснений есть этот файл.

| Файл | Что это | Состояние |
|---|---|---|
| `list-warp.txt` | хосты, к которым применяется дурение в WARP-стратегии | только то, что относится к туннелю |
| `list-general.txt` | общий список заблокированных ресурсов | из апстрима zapret |
| `list-google.txt` | отдельный список для сервисов Google | из апстрима |
| `list-exclude.txt` | домены, которые дурение не трогает | из апстрима |
| `*‑user.txt` | место для ваших дополнений (пустые по умолчанию) | правьте смело |
| `ipset-all.txt` | IP/подсети для правил `--ipset=` | **пуст** (см. ниже) |
| `ipset-exclude.txt` | локальные диапазоны, которые не дурим | RFC1918 + loopback |

## Почему `ipset-all.txt` пуст

Раньше в нём лежал единственный адрес `203.0.113.113/32` — это `TEST-NET-3`
из RFC 5737, адрес-заглушка для документации. Правила вида

```
--filter-tcp=80,443,8443 --ipset="lists/ipset-all.txt" ...
```

не совпадали ни с чем, то есть часть ветвей в `general_*.bat` была мёртвой.

Сейчас файл пуст, а парсер (`core/strategy.py`) видит, что адресов нет, и убирает
такие правила из argv. Убирает **целиком**, а не только `--ipset=`: иначе правило
`--filter-tcp=80,443,8443` осталось бы без ограничения по адресам и задурило бы
весь трафик на этих портах.

## Как включить `--ipset`-ветки

Заполните `ipset-all.txt` адресами или CIDR построчно:

```
104.16.0.0/12
1.2.3.4
```

После перезапуска приложения правила с `--ipset=` вернутся в argv автоматически.

## `list-warp.txt` — самый важный для маскировки

В нём должны быть только хосты, к которым приложение реально подключается
через туннель. Широкие домены (`cloudflare.com` целиком) тянут в дурение весь
трафик к Cloudflare-CDN — а за Cloudflare сегодня половина интернета. Это лишний
шум и лишняя заметность.
