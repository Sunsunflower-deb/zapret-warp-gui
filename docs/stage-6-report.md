# Отчёт по этапу 6 (релиз 1.3.0): автоподбор стратегии

Задача этапа — убрать главный разрыв: «в репозитории 24 `.bat`, а какой из них
работает на моей сети — неизвестно». В zapret для этого есть `blockcheck.sh`,
в GUI не было ничего.

## Как это работает

```
build_candidates()  →  16 кандидатов
        │
        ├─ materialize()  →  временный .bat  →  strategy.parse_file()  (тот же парсер)
        │
        ├─ prepare()      →  engine.stop() + engine.start_parsed() + прогрев
        │
        ├─ probe_fn()     →  attempts × цели (WARP endpoint, YouTube)
        │
        └─ score_results() → ok_rate, leak_rate, median_rtt → score
                │
                └─ _rank() → победитель → export('tuned.bat') + apply(config)
```

Ключевое решение: кандидат проходит **через тот же парсер**, что и штатные
стратегии (`%BIN%`, `%LISTS%`, `%Fooling%`, GameFilter, мёртвый ipset). Иначе
подбор проверял бы одно, а запускалось другое — классическая ловушка в таких
инструментах.

## Формула оценки

```
score = 100 × ok_rate − 60 × leak_rate − min(40, median_rtt / 50)
```

* `60 × leak_rate` — утечка (`reset`/`tls_*`) означает, что подделка дошла до
  сервера и испортила поток. Такая стратегия не «просто медленная»: одна утечка
  на две пробы (leak_rate = 0.5) отнимает 30 баллов;
* `min(40, rtt/50)` — скорость влияет, но не решает: 2 секунды медианы стоят
  40 баллов, дальше штраф не растёт;
* при равенстве score побеждает кандидат без утечек (`_rank`).

## Что проверено

* `python -m ruff check .` — чисто.
* `python -m pytest -q` — **231 passed, 5 skipped**.
* `python cli.py tune --dry-run` — 16 кандидатов, тексты корректны.
* `python cli.py tune` без прав администратора — сразу сообщает об этом и
  выходит с кодом 2 (не пытается перезапускать winws вслепую).
* Каждый из 16 кандидатов проверен тестом на разбор реальным парсером: нет
  `%BIN%`/`%Fooling%` в argv, нет отдельного токена `-`, hostlist на месте.

**Не проверено:** сам живой прогон (`cli.py tune` с правами администратора) —
в этой сессии нет elevation, а подбор перезапускает `winws.exe`. Логика прогона
покрыта тестами с внедрёнными зависимостями (перезапуск, пробы, часы), но
поведение на реальной сети надо подтвердить.

## Найденные баги

* **`_rank()` выбирал худшего кандидата.** Две ошибки в одной функции: `-score`
  при сравнении через `max()` переворачивал порядок, а флаг утечек был направлен
  так, что побеждал именно утекающий кандидат. Оба случая теперь закрыты тестами
  (`test_rank_prefers_clean_over_leaky`, `test_tune_picks_working_candidate`) и
  описаны в docstring, чтобы не вернулись.

## Как пользоваться

```bash
python cli.py tune --dry-run     # посмотреть 16 кандидатов
python cli.py tune               # прогон (Windows: от администратора)
python cli.py tune --apply       # сохранить победителя
python cli.py check              # убедиться, что стало лучше
```

После `--apply` победитель лежит в `strategies/tuned.bat` — обычный текстовый
файл, его видно в списке стратегий и можно править руками.
